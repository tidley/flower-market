# Flower Market v0.1 (Blossom Merkle Audit)

A retrieval-bounty market for proving data availability and paying storage operators.

## Goals

- Incentivize **fast and reliable retrieval**
- Keep verification **objective** using Merkle inclusion proofs
- Enable **open participation** through paid replication

## Core Mechanics

1. A challenger posts a challenge for `(blob_id, merkle_root, leaf_index, nonce, deadline)`.
2. Responders submit `commit` first (hash of full response) to prevent front-running.
3. Responders reveal `leaf + proof + metadata` in reveal window.
4. Verifiers check proof correctness and timing.
5. Top 3 valid responders are paid: **15 / 10 / 5 sats**.
6. Reliability bonus adds msats for long-run consistency.

## Reputation + Bonus

Maintain separate rolling scores:

- `latency_score`: response speed percentile across last N rounds
- `reliability_score`: success ratio across last N rounds

Bonus example:

- base bonus: `+1000 msat`
- multiplier from reliability tier:
  - >= 95%: x1.0
  - >= 90%: x0.5
  - otherwise: x0

## Replication Marketplace

- Node without data can request transfer from a holder and pay e.g. `5 sats`.
- Receiver becomes eligible in the **next epoch** (cooldown) to prevent instant sniping.
- Transfer can be verified by sampled challenge before eligibility is granted.

## Anti-Gaming Controls

- commit-reveal to prevent answer copying/front-running
- deterministic challenge seed from public entropy source
- strict deadline checks
- replay protection (`challenge_id`, commit nonce)
- minimum sample size per epoch

## Data Model (draft)

- `challenge`
  - `challenge_id`
  - `blob_id`
  - `merkle_root`
  - `leaf_index`
  - `nonce`
  - `commit_deadline`
  - `reveal_deadline`
  - `payout_schedule` (15/10/5)
- `commit`
  - `challenge_id`
  - `responder`
  - `commit_hash`
  - `ts`
- `reveal`
  - `challenge_id`
  - `responder`
  - `leaf_data_hash`
  - `leaf_value` (or encrypted reference)
  - `proof` (sibling hashes + direction bits)
  - `response_ts`
- `settlement`
  - `challenge_id`
  - ranked winners
  - base payout + bonus payout
  - tx/payment refs

## Verification Rules (draft)

1. `commit_hash == H(challenge_id || responder || leaf || proof || nonce)`
2. Proof reconstructs `merkle_root`
3. `response_ts` inside reveal window
4. First valid commit timestamps determine rank
5. Duplicate responder entries invalid
